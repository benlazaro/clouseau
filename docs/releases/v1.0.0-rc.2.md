Title: Clouseau 1.0.0-rc.2 — Find and update plugins from the Plugin Manager

## The second release candidate for Clouseau 1.0

This release candidate makes plugins easier to find and keep up to date, and lets you
collapse long JSON and `toString()` messages in the detail panel. As with rc.1, please
try it on your own logs and [open an issue](https://github.com/benlazaro/clouseau/issues) for
anything that crashes, loses data or doesn't work as the guide says. If about two weeks go by
without a serious bug, it becomes 1.0.

### Find plugins, not just any library
**Tools → Plugins… → Browse** used to search the whole repository, so typing a word on Maven
Central brought back every Java library that matched it. Now Browse opens on the Clouseau
plugins in the repository you select:

- **Maven Central** lists the plugins on Clouseau's plugin list, each at its latest version.
  No one has published a plugin yet, so the list starts empty. If you write one, the
  [developer guide](https://benlazaro.github.io/clouseau/guide/developers.html#naming-and-publishing)
  explains how to add it.
- **Your company's Nexus** lists every artifact named like a plugin (`<name>-clouseau-plugin`)
  as soon as it's deployed. Nothing needs registering.
- **Type to filter** by name, description or what a plugin adds: `source` shows every plugin
  that adds a live source. A new **Adds** column says what each one brings.
- **Press Enter** to search the whole repository for a plugin that isn't on the list. The
  search shows only plugins, never other libraries that match. On Nexus, any part of a name
  works now (`fmt` finds `logfmt-clouseau-plugin`), and every version of each plugin is listed,
  even on servers whose search finds only some of them. The list shows each plugin's
  **Latest** version, and a search says how many versions of how many plugins it found. Clear
  the field to go back to the plugins.
- Results show the date each version was published and can be sorted by any column. Clouseau
  remembers the sort and the column widths. A slow repository shows how long it has been
  searching, and **Cancel** stops it.
- Browse opens on the repository you used last.

### Plugin updates
- **Installed** shows the version you have. When the repository has a newer one, the plugin's
  row shows the new version and a green arrow; click the arrow (or **Update to …** in its
  details) to replace your version with it. Browse offers **Update** too.
- **Downgrade.** On a version older than the one you have, Browse offers **Downgrade**. It asks
  first, and Clouseau offers the newer version again as an update.
- After an install, update or downgrade, a note over the list says what happened, such as
  "Updated logfmt example from 1.0.0 to 1.1.0", or that the plugin didn't load.
- **Clouseau tells you.** A few seconds after it starts, then once a day, Clouseau checks your
  plugins. One small notice lists every plugin with an update, and **Tools → Plugins…**
  shows how many there are. **Later** means you won't hear about those versions again, only
  about newer ones.
- Plugins never update by themselves: you always choose. The **Tell me about new versions**
  setting turns these notices off along with Clouseau's own.
- A plugin is checked against the repository you installed it from. A plugin you copied
  into the `plugins` folder yourself is checked only if it's on the plugin list.

### Collapse JSON and toString() in the detail panel
- A pretty-printed JSON object or array, or an object's `toString()` spread over several
  lines, now has a **▾** beside the line where it starts. Click it to fold it into one line,
  such as `"items": [ … 12 items ],`, and click again (or on the `… 12 items`) to open it.
- Right-click the panel for **Collapse All** and **Expand All** (`Ctrl+Shift+-` and
  `Ctrl+Shift+=`). After Collapse All, open a big payload one level at a time.
- Copying always gives you the full text. Find in the entry counts matches in collapsed
  parts too, and stepping to one opens it. The next entry you select opens in full.

### Tables
- **A third click on a column header clears the sort.** The first click sorts ascending,
  the second descending, and the third goes back to the table's own order. In the log table,
  that's the order of the file.

### Fixes
- **Removing a plugin no longer crashes an open tab.** Selecting a row that the removed
  plugin's formatter used to handle showed "Clouseau ran into a problem". Open tabs now drop
  the plugin's formats right away.
- **A broken plugin formatter no longer brings up the crash window.** One that fails is
  skipped for that message, and the message shows as logged.
- **A long auto-highlight keeps its delete button.** In **Tools → Auto-Highlights…**, a rule
  too long for the list now ends in "…", and the duplicate and delete icons stay in view.

### For plugin authors
- **Check a plugin without opening Clouseau:**
  `java -jar clouseau-edge.jar --check-plugin your-plugin.jar sample.log`. It loads the JAR as
  Clouseau does, runs your parsers, formatters and highlighters on the sample, and reports
  each finding as OK, WARN or FAIL. It catches mistakes that are hard to see in the window:
  a parser that isn't thread-safe, times with an offset that move with the log's timezone, a
  JAR that bundles the API, lines a built-in parser reads first. The exit code is 1 when
  something fails, so it can run in CI. See
  [Checking a plugin](https://benlazaro.github.io/clouseau/guide/developers.html#checking-a-plugin).
- **Writing one with a coding assistant?** Point it at
  [llms.txt](https://benlazaro.github.io/clouseau/llms.txt): the build file, every extension
  point and its rules, and the check, on one page.
- **The example plugin is a template now.** Its folder builds on its own: copy it, rename it,
  build it.
- **Name your plugin `<name>-clouseau-plugin`**, and use that name for its artifact, JAR and
  `Plugin-Id`. `clouseau-<name>-plugin` is kept for plugins the Clouseau project publishes,
  as Maven does for its own plugins. Browse finds plugins on Nexus by this name, and the
  plugin list accepts only names that follow it.
- The example plugin is now `logfmt-clouseau-plugin`.
- `LogFormatter`'s documentation now says what it gets, in what order formatters run, that
  they run on the event thread, and what happens when one fails.
- The plugin API is unchanged (0.3.0). Plugins built for 0.17 and later keep working.

### Upgrading
- Close Clouseau before you start the new version.
- **From 1.0.0-rc.1:** replace the old app with the new one; your data is in your home
  folder (`~/.clouseau`, or `C:\Users\<you>\.clouseau` on Windows) and carries over.
- **Windows, from 0.18 or earlier:** those versions kept your data in the `data` folder next
  to `Clouseau.exe`. Before you delete the old `Clouseau` folder, either copy that folder's
  contents to `C:\Users\<you>\.clouseau`, or move the `data` folder next to the new
  `Clouseau.exe` to keep using Clouseau portable.
- A new download is a new app to your system, so you may have to allow it once more. See
  [Installing](https://benlazaro.github.io/clouseau/guide/installing.html).
